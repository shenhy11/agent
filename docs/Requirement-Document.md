# 智能客服 Agent 业务需求文档 (PRD)

## 1. 业务概述
目前企业拥有数百万终端客户，面临极大的并发咨询压力。传统基于规则的客服机器人无法识别复杂意图并缺乏连续交互能力。本系统旨在建设一个 7x24 小时的高级 AI Agent，接管至少 70% 的日常咨询与轻业务操作。

## 2. 目标角色与应用场景
- **C端用户**：在 APP、微信或官网发起对话，查询物流、办理退票、故障排查。
- **坐席客服**：Agent 无法处理时进行的“人工转接”，无缝阅读之前 Agent 沟通的上下文。
- **知识库管理员**：上传并维护企业的知识库更新（如双11活动规则）。

## 3. 核心功能需求

### 3.1 智能问答模块
- **单/多轮对话交互**：支持记住上下文的语义沟通。
- **实时流式反馈 (Streaming)**：必须采用类似 ChatGPT 的打字机效果呈现给客户端，优化用户心理预期。
- **多模型兜底路由**：主力选择通义千问大模型，如偶发宕机，需能低成本切换到替代模型。

### 3.2 任务型对话 (工具执行)
客服不仅负责问答，需能够执行业务系统级别的查询与变更：
- **订单查询场景**：当识别到用户询问“我的手机还有多久送到”，需识别包裹号并调用《获取物流轨迹接口》，整理回答。
- **工单流转场景**：当识别用户为情绪激烈的投诉或人工操作受限，能够收集相关要素并调用《创建内部客服工单接口》。
- **账号操作**：可以查询余额、重置密码（需对接认证上下文）。

### 3.3 企业知识库管理
- **知识入库**：管理后台支持上传文档 (TXT / PDF / MD)。系统需在 5 分钟内完成解析与向量化。
- **时效性与隔离限制**：保证特定的活动答案只在活动期间有效，可通过 Metadata 过滤控制生效范围（例如按“租户ID”或“类别”切片查询）。

## 4. 全局非功能性需求
- **并发与高可用**：常态支撑 1,000 QPS 的并发问答，峰值 10,000 QPS（结合阿里云弹性伸缩及 Token 队列拦截机制）。
- **安全与合规**：
  - 脱敏处理：禁止将用户敏感隐私信息（手机号、身份证号、支付密码）提交给第三方公有云模型。
  - 兜底校验：对于大模型输出的退款金额或决策必须叠加正则与业务边界检查。
- **可观测性**：需记录每一条进出 Message 的时间、Token 消耗数量，支持运营层对“回答不准”的点踩记录进行追溯和再训练（评估）。
